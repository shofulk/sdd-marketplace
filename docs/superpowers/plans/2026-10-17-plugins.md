# SDD Plugins (Track B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The four plugins of marketplace `sdd` — `engineering-paved-path`, `research-tools`, `architecture-review`, `sdd-engineering` — at 1.0.0, ported from DevDigest, generalized, with their guards, trace hooks, tests and two evals, after the spikes C1–C7.

**Architecture:** Plugins live under `plugins/<name>/` in the Claude Code standard layout. Hook code shared by several plugins has one canonical copy in `tools/hooklib/`, synced into each plugin's `hooks/lib/` (a plugin cannot reference files outside its root). Host projects configure the set through `.sdd/config.json`. Agents and skills are Markdown; hooks and scripts are Node ESM with `node:test` tests.

**Tech Stack:** Node ≥ 20 (ESM, `node:test`, no runtime dependencies), Markdown agents/skills, Claude Code 2.1.293 (`claude plugin validate --strict`, `claude plugin eval`).

**Spec:** `docs/specs/2026-10-17-plugin-set-design.md` (approved). Read it first; this plan argues from it.

**Source (read only):** the DevDigest checkout whose path the kickoff gives as `$DEVDIGEST`. Never write there.

## Global Constraints

- Marketplace `sdd`, repo `shofulk/sdd-marketplace`; plugins exactly `engineering-paved-path`, `research-tools`, `architecture-review`, `sdd-engineering`; all at version `1.0.0` when this plan ends.
- `sdd-engineering` depends on the other three, each `^1.0.0`; `architecture-review` depends on `engineering-paved-path ^1.0.0`. No other edges.
- A plugin agent's frontmatter uses only `name, description, model, effort, maxTurns, tools, disallowedTools, skills, memory, background, isolation, color`; never `hooks`, `permissionMode`, `mcpServers`, `initialPrompt` (ignored in plugins — spec §2).
- A skill dispatches agents by namespaced name `<plugin>:<agent>`; a bare `subagent_type` does not reach a plugin agent (spec §2).
- Paths inside a plugin are written `${CLAUDE_PLUGIN_ROOT}/...` in skill and agent Markdown (substituted inline); that variable is not in the Bash tool's environment. Hook commands quote it: `node "${CLAUDE_PLUGIN_ROOT}/hooks/..."`.
- Not ported (spec §3.3): product specs, plans, retros, secrets (`.mcp.json`, `settings.local.json`, `.env`), cache (`.harness/`, `.pr-review/`, eval runs), DevDigest-specific instructions. No file under `plugins/` except `NOTICE` contains: `DevDigest`, `dev-digest`, `server/`, `client/`, `reviewer-core`, `e2e/`, `mcp-server`, `pnpm --dir`, `INSIGHTS.md`, `AGENTS.md`, `TESTING.md`, `.claude/scripts`, `.claude/hooks`, `.harness/`.
- `next-best-practices` is not copied; `nextjs-app-router` is written from nextjs.org docs (spec §1, §4).
- Every plugin has `README.md`, `CHANGELOG.md` (Keep a Changelog: `## [1.0.0] - YYYY-MM-DD`), `NOTICE`. A `NOTICE` names each copied file's source path and carries the source's copyright line and MIT text (DevDigest upstream `ai-agentic-engineering-neo/dev-digest`, MIT; `mcollina/skills`, MIT).
- Project contract `.sdd/config.json` (spec §3.4), keys and defaults: `context: []`, `specs: "specs/"`, `plans: "docs/plans/"`, `runs: ".sdd/runs/"`, `checks: {}` as `{ "<pkg>": { "typecheck"?, "lint"?, "test"?, "arch"? : "<command>" } }`, `routing: null`, `agents: []`, `skills: {}`; plus two keys spec §3.6/§3.9 imply: `checksDir: ".sdd/checks/"`, `retros: "docs/retros/"`.
- Trace (spec §3.8): each plugin's SessionStart hook appends `{"time","session_id","plugin","version"}` to `$CLAUDE_PROJECT_DIR/.sdd/trace.jsonl`, version from `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`.
- Hooks fail open on their own errors (exit 0 with a stderr note); a block is exit 2 with the reason on stderr.
- Work happens on this track's branch in its own worktree. Commit after each task, locally; no `git push`, no tags, no GitHub repository, no PR, no Pages. Commit messages carry no attribution lines.
- Do not touch `site/`, `.github/`, or `.gitignore` — Track A owns them.

## Review Focus

- A hook receives empty or malformed stdin → it allows (exit 0) and writes one stderr line; it never blocks every command. Test: B2.
- `.sdd/config.json` is missing or invalid JSON → defaults apply and the guard still decides; nothing throws. Test: B2.
- A blocked command hides in a chain, a subshell or after a comment (`ls && git push`, `(git push)`, `echo x; git commit -m y`) → still blocked; the same words inside quotes or a heredoc body are data and pass. Test: B2.
- Two plugins both register PreToolUse Bash hooks → each blocks only the `agent_type` values it was given; the main thread (no `agent_type`) is never blocked by an agent guard. Test: B2.
- The project directory path contains a space → the trace hook still writes `.sdd/trace.jsonl` there. Test: B2.
