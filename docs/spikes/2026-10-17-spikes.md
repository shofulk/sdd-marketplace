## C1 — a hook's block in the eval trace

Draft plugin `spk-guard`: PreToolUse `Bash` hook `node "${CLAUDE_PLUGIN_ROOT}/hooks/block.mjs"`, which
exits 2 with `SPIKE-BLOCK: git push is blocked by spk-guard` on stderr when the command contains
`git push`; one case whose `scaffold_script` builds `repo/` and the bare `remote.git/` with `main` and
`origin/HEAD`.

```
claude plugin eval ./spk-guard --scaffold --allow-tools Bash --ablation none --runs 1 --model haiku \
  --trust-plugin --no-publish --keep-temp --threshold 0 --json ../out/c1-block.json
```

- Grader `regex`, `target: trace`, `pattern: SPIKE-BLOCK`: **passed** ("matched SPIKE-BLOCK").
- The trace's `tool_result` for the blocked call reads
  `PreToolUse:Bash hook error: [node "<plugin>/hooks/block.mjs"]: SPIKE-BLOCK: git push is blocked by spk-guard\n\nThis hook comes from the spk-guard@inline plugin.`
- The model repeated the marker in its own reply too, so a grader that must prove the hook fired
  should match the hook's line, e.g. `hook error: \[[^\]]*\]: SDD-PUSH-BLOCKED`, not the bare marker.
- `tool_used: Bash` with `input_match: git push` passed. Cost $0.0070.

## C6 — push to a local bare remote inside the sandbox

Same fixture, plugin `spk-noguard` (SessionStart hook only, no PreToolUse hook). Three runs:

- `c6`: invalid — the copied plugin still carried the blocking hook (a copy error in the spike), so
  the push was blocked; not counted. Cost $0.0071.
- `c6b`: `/opt/homebrew/bin/git` with `--receive-pack=/opt/homebrew/bin/git-receive-pack`. The push
  fails: `remote: git: error: couldn't create cache file '/var/folders/.../T/xcrun_db-…'
  (errno=Operation not permitted)`, `xcode-select: Failed to locate 'git'`, `! [remote rejected] main
  -> main (unpacker error)`; `result.txt` equals `initial-sha.txt`. Cost $0.0046.
- `c6c`: `export PATH="/opt/homebrew/bin:$PATH"; hash -r` first. `command -v git` and `which -a git`
  still print only `/usr/bin/git`; `git --version` exits 72 with the same xcrun error. Cost $0.0041.

A sandbox probe (`c1-probe2`) showed `PATH` starting with `/opt/homebrew/...`, `git is /usr/bin/git`,
`/opt/homebrew/bin/git --version` → `git version 2.53.0`, and `node -e "execFileSync('git',…)"` →
`git version 2.53.0` (Node's lookup finds Homebrew git; the sandboxed shell's lookup does not).

Verdict: on this machine a git push from the eval's sandboxed Bash cannot reach a local bare remote,
because every shell-resolved `git` (including the remote-side `receive-pack` helpers) is the Xcode shim,
which cannot write its cache outside the sandbox. Fallback (spec): the 1.1.0 behaviour is covered by its
deterministic cases. Because C1 holds, the 1.1.0 eval can still grade `tool_used` (the push was tried) and
the trace regex (the hook blocked it); its `result.txt` grader (`git ls-remote` after the attempt) cannot
be produced in this sandbox and is dropped from the local run.

## C2 — two channels via the settings `path` field

Scratch marketplace repository (`git`, `file://` URL) with four plugins (`spk-paved`, `spk-research`,
`spk-arch` → `spk-paved ^1.0.0`, `spk-top` → the three `^1.0.0`), tags `<name>--v1.0.0` on the first
commit, then `spk-top` bumped to 1.1.0 and tagged `spk-top--v1.1.0`. Root catalog `spk-latest` (relative
sources); second catalog `.claude-plugin/stable/marketplace.json` named `spk-stable`, entries
`{"source":"git-subdir","url":"file://…/mkt","path":"plugins/<name>","ref":"<name>--v1.0.0"}`.

- Registration: a settings file (`--settings`, one `claude -p` turn, `CLAUDE_CODE_PLUGIN_CACHE_DIR` in
  scratch) declaring `spk-latest` `{source: git, url}` and `spk-stable`
  `{source: git, url, path: ".claude-plugin/stable/marketplace.json"}`. `claude plugin marketplace list
  --json` then lists both. **The `path` field works.** (Declared in an untrusted project's
  `.claude/settings.json`, neither registers — `marketplace list` prints `[]`, as the settings docs say;
  `marketplace update` and `install` do not register a declared marketplace either: it happens at
  session start.)
- Pin: `claude plugin install spk-top@spk-stable --scope project` → `spk-top@spk-stable 1.1.0`,
  `gitCommitSha 6df6df0…` (HEAD), dependencies `1.0.0-7762ee995a91` (tag commit). Repeated with `sha` added
  to every entry: `spk-top 1.1.0`, `gitCommitSha fc5514a…` (HEAD again). **The `ref`/`sha` pin is not
  honored** when the catalog is cloned from the same repository the `git-subdir` entries point at.
- Control: the same entry form in a catalog added as a `file` source (no clone) honored the ref
  (`v-ref` → `1.0.0`, `gitCommitSha 7762ee9…`).
- Docs (`plugins/marketplace-reference`): a `github` plugin source has fields `repo`, `ref`, `sha` and
  no `path`, so the spec's `{source: "github", repo, ref}` cannot point at `plugins/<name>`; `claude
  plugin validate --strict` accepts the stray `path` key silently.

Fallback applied (spec "If wrong"): **a `stable` branch with its own marketplace name.** Branch `stable`
cut at the 1.0.0 tag commit, its root catalog renamed `spk-stable-b`; registered as
`{source: git, url, ref: "stable"}` next to `spk-latest`. `claude plugin install spk-top@spk-stable-b
--scope project` → `spk-top 1.0.0` (`856c4e6…`), dependencies `1.0.0-7762ee995a91`, all enabled, no
errors. Caveat: measured with `file://` URLs; the GitHub form is unverified until the repository is
pushed (the user's word).

## Changes to the plan

1. **Stable channel (C2).** The stable channel is a `stable` branch whose root
   `.claude-plugin/marketplace.json` is named `sdd-stable` (relative sources, the plugins at their
   released versions), not a second catalog file pinning tags. B9's README documents it; the release
   tags `<name>--v<version>` stay (dependency ranges resolve against them).
2. **B10 smoke graders (measured above).** `tool_used: Skill` cannot see a slash-invoked
   `disable-model-invocation` skill, and B7 keeps `disable-model-invocation: true` on run-plan. The smoke
   case therefore sends `/sdd-engineering:run-plan` with no argument and grades by `regex` (the four
   plugins' components in the trace's `init`, and run-plan's own no-argument reply in the last message)
   instead of `tool_used: Skill`.
3. **Every eval run** adds `--trust-plugin` (non-interactive trust), `--no-publish` (the report stays
   local) and `--output-dir` outside the repository; `--json` writes the saved report.
4. **1.1.0 eval (C6, next phase).** Graded by `tool_used` and the trace's hook line only on this machine;
   the deterministic cases carry the behaviour.

## Interface changes

- **Stable marketplace (Track A reads it).** No `.claude-plugin/stable/marketplace.json`. The stable
  catalog is `stable:.claude-plugin/marketplace.json` (branch `stable`), `name: "sdd-stable"`, entries
  `{name, source: "./plugins/<name>"}`; a plugin's stable version is the `version` in
  `stable:plugins/<name>/.claude-plugin/plugin.json`. Until the branch exists, every plugin is "stable:
  not released". Users add it with `claude plugin marketplace add shofulk/sdd-marketplace#stable`, or in
  settings `{"extraKnownMarketplaces": {"sdd-stable": {"source": {"source": "github", "repo":
  "shofulk/sdd-marketplace", "ref": "stable"}}}}`, and install `sdd-engineering@sdd-stable`.
